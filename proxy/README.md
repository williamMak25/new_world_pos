# Local HTTPS proxy (phone-as-scanner setup)

Browsers only allow camera access (`getUserMedia`, used by the barcode
scanner) on a secure context: `https://` or exactly `localhost`. A phone
hitting your dev machine over WiFi uses your LAN IP, e.g.
`http://192.168.1.113:3000`, which is neither — so the camera would be
blocked there.

The `proxy` service in `docker-compose.yml` (Caddy) fixes this by serving
both the frontend and the backend API on a single HTTPS origin, using a
locally-trusted cert generated by [mkcert](https://github.com/FiloSottile/mkcert).

## Access the app

- Desktop: **https://localhost** (not `http://localhost:3000` anymore —
  see "Why :3000 stopped working" below)
- Phone (same WiFi): **https://\<this machine's current LAN IP\>** — check
  with `ip -4 addr show` (look for the address on your WiFi interface, e.g.
  `wlp3s0`). The cert currently covers `172.20.10.3` and `192.168.1.113`;
  if you're on neither, see "If your LAN IP changes" below.

Ports 3000/8000 are still exposed for direct debugging (curling the API,
etc.) but the browser app should be opened through the proxy on 443.

## Trusting the certificate

### On this machine (optional, removes the browser warning)

```
~/.local/bin/mkcert -install
```

Prompts for your sudo password once; after that `https://localhost` is
trusted by desktop browsers with no warning.

### On the phone (required for the camera to work)

1. Connect the phone to the same WiFi as this machine (or the phone's own
   hotspot, if that's what this machine is tethered to).
2. In the phone's browser, go to `http://<lan-ip>/rootCA.pem`
   (plain HTTP — no trust needed yet, that's the whole point of this step)
   and download it.
3. Install it as a trusted root:
   - **iOS**: Settings → General → VPN & Device Management → tap the
     downloaded profile → Install. Then Settings → General → About →
     Certificate Trust Settings → enable full trust for it.
   - **Android**: Settings → Security (→ Encryption & credentials) →
     Install a certificate → CA certificate → pick the downloaded file.
     Exact wording varies by Android version/OEM.
4. Visit `https://<lan-ip>/products`, log in, and the camera prompt
   on the Scan button should work.

## If your LAN IP changes

**This bit us already once**: the machine hopped from `192.168.1.113`
(home WiFi) to `172.20.10.3` (a hotspot network) mid-session, and the
proxy silently hung on the old IP until the cert/CORS were regenerated for
the new one. If `https://<lan-ip>` stops responding, check `ip -4 addr
show` first — the IP has probably just changed. To fix it, regenerate the
cert (this appends the new IP without dropping the old ones, so it keeps
working after switching back):

```
cd proxy/certs
~/.local/bin/mkcert -cert-file dev-cert.pem -key-file dev-key.pem localhost 127.0.0.1 172.20.10.3 192.168.1.113 <new-lan-ip> ::1
docker compose restart proxy
```

Also add `https://<new-lan-ip>` to `ALLOWED_CORS_ORIGINS` in
`docker-compose.yml` (backend service), then `docker compose up -d` to
apply it.

## Why :3000 stopped working directly

The frontend now sends API requests to a relative path (same origin the
page was loaded from) instead of a hardcoded `http://localhost:8000`, so
that it works identically whether you're on `https://localhost` or
`https://<lan-ip>`. That means opening the frontend on its own port
(`:3000`) directly no longer has a backend to talk to at that origin —
always go through the proxy (`https://localhost` or the LAN IP) instead.
