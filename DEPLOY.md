# Deploying for free, without a credit card

This stacks four services, each with a permanent free tier that doesn't ask
for a card:

| Piece                     | Provider | Why |
| -------------------------- | -------- | --- |
| Postgres                   | [Neon](https://neon.tech)    | Free forever, serverless, scales to zero when idle |
| Redis (background jobs)    | [Upstash](https://upstash.com) | Free forever, serverless, 500k commands/mo |
| Backend (Litestar API)     | [Render](https://render.com)  | Free web service, deploys straight from `backend/Dockerfile` |
| Frontend (Next.js)         | [Vercel](https://vercel.com)  | Free tier, built for Next.js |

Caveat: free Render web services spin down after 15 minutes idle, so the
first request after a quiet period takes ~30-60s to wake up. Fine for a demo
or personal project; not for something that needs to always be instantly
available.

## 1. Postgres — Neon

1. Sign up at [neon.tech](https://neon.tech) (GitHub/Google login works, no
   card).
2. Create a project, then open the connection string it gives you. It looks
   like:
   ```
   postgresql://user:pass@ep-xxxx-pooler.region.aws.neon.tech/neondb?sslmode=require
   ```
3. Rewrite the scheme from `postgresql://` to `postgresql+psycopg://` (this
   backend uses the psycopg driver) — keep everything else, including
   `?sslmode=require`. That full string is your `DATABASE_URL`.

## 2. Redis — Upstash

1. Sign up at [upstash.com](https://upstash.com) (no card).
2. Create a Redis database (any region close to your Render region).
3. Copy the **TLS** connection string — it starts with `rediss://` (double
   `s`, not `redis://`). That's your `SAQ_REDIS_URL`.

## 3. Backend — Render

This repo includes `render.yaml`, so Render can deploy it as a Blueprint:

1. Sign up at [render.com](https://render.com) (no card) and connect your
   GitHub account.
2. **New > Blueprint**, pick this repo. Render reads `render.yaml` and
   proposes a `pos-backend` free web service built from `backend/Dockerfile`.
3. Before the first deploy, fill in the blueprint's blank env vars:
   - `DATABASE_URL` → the Neon string from step 1
   - `SAQ_REDIS_URL` → the Upstash `rediss://` string from step 2
   - `ALLOWED_CORS_ORIGINS` → placeholder for now, e.g.
     `["https://placeholder.vercel.app"]` — you'll come back and set this to
     your real Vercel URL after step 4.
   - `SECRET_KEY` is auto-generated by Render — leave it.
4. Deploy. On boot the container runs migrations (`app database upgrade`),
   seeds default roles, then starts the API. Once live, note the service URL,
   e.g. `https://pos-backend.onrender.com`. Check
   `https://pos-backend.onrender.com/health` returns
   `{"database_status":"online",...}`.

## 4. Frontend — Vercel

1. Sign up at [vercel.com](https://vercel.com) (no card) and import this repo.
2. Since the frontend lives in a subdirectory, set **Root Directory** to
   `frontend` in the project's import settings (Vercel auto-detects Next.js
   once you do).
3. Add an environment variable:
   - `NEXT_PUBLIC_API_URL` → your Render backend URL from step 3, e.g.
     `https://pos-backend.onrender.com`
4. Deploy. Note the resulting URL, e.g. `https://your-app.vercel.app`.

## 5. Wire CORS back up

Go back to the Render service's environment settings and update
`ALLOWED_CORS_ORIGINS` to your real Vercel origin:

```
["https://your-app.vercel.app"]
```

Save — Render redeploys automatically. This step is required: the
refresh-token cookie only works cross-origin when the backend's CORS list
exactly matches the frontend's origin (see the "How auth works" section in
`README.md`).

## 6. Try it

Open your Vercel URL, sign up, and follow the onboarding flow to create a
business and first store.

## Notes / gotchas

- **Cold starts**: free Render services sleep after 15 min idle; the first
  request after that takes 30-60s while it wakes up.
- **Neon scale-to-zero**: the free Postgres branch also suspends after 5 min
  idle and wakes on the next query, adding a similar delay to first requests.
- **Upstash limits**: 500k commands/month, 256MB data — background job usage
  in this app (SAQ) is light, so this is generous headroom for personal use.
- Camera-based barcode scanning needs HTTPS, which both Render and Vercel
  provide by default — no separate reverse proxy (like the local `proxy/`
  service in `docker-compose.yml`) is needed in this setup.
